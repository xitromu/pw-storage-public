# Модель угроз

Русская версия — первична; сверяй формулировки с кодом, а не с переводом.

## Границы доверия

| Зона | Что в ней | Кто в нём доверенный |
|---|---|---|
| Файл `vault.kdbx` | все значения, KDF Argon2id | никто, пока не введён пароль |
| TPM этого ПК | ключи каталога, удалённого кода, пакетов служб | закрытая часть не извлекается ни API, ни драйвером |
| Посредник (память процесса) | расшифрованная база, одобренные строки | только пользователь, запустивший посредника |
| Канал | номера строк, сервисы, имена ключей, значения по запросу | процессы той же учётной записи |
| Владелец | пароль, подтверждения, часть ключа восстановления | — |

Всё, что за пределами таблицы (другая учётная запись, другой компьютер, git, чат, журнал), считается
враждебным и должно утечь максимум в бесполезном виде.

## От чего это защищает

- **Секреты в репозиториях и в чате.** `pw.py` и клиент не имеют команды печати значения — ограничение
  заложено в интерфейс, а не в соглашение. В `logs/access.log` бывают имена и номера строк, значений нет.
  Подключение проекта — блок в `CLAUDE.md`, который прямо запрещает агенту читать `secrets.env` и резервные
  копии; файлы секретов программа только находит и показывает, сама не читает.
- **Случайный коммит файла хранилища.** `data/`, `test_data/`, `logs/`, `*.kdbx`, `recovery.json`,
  `settings.json` и конфигурации служб в `.gitignore`.
- **Кража или копирование `vault.kdbx`.** Без пароля остаётся только подбор под Argon2id 1024 МиБ × 4 прохода:
  это медленно намеренно. Ограничение попыток (5) относится к окну программы; сам файл перебирают вне её,
  поэтому стойкость держится на длине пароля, а не на счётчике.
- **Копия `catalog.bin`, `remote.bin`, пакета службы на чужой машине.** Они зашифрованы ключами TPM этого ПК
  и привязаны к машине (а пакет службы — ещё и к её SID), так что это беспорядочные байты.
- **Выдача «промахом».** Значение отдаётся только строке, не менявшейся с момента одобрения, и только проекту,
  которого владелец коснулся. `save_token` сверяет прежнее значение (`expected`) и не даёт перезаписать токен,
  прочитанный вслепую.
- **Долго живущий доступ.** Срок максимум `grant_hours` (по умолчанию 12 ч), посредник без дела закрывается и
  выгружает файл из памяти, `close` снимает доступ сразу и у всех сессий проекта.
- **Разрастание прав.** `ALL` — «можно запросить», а не «выдано»: одобрение добавляет проект в список
  конкретной строки. Неиспользуемые строки и лишние проекты показывает окно «Чистка».
- **Потеря флэшки с резервной копией.** Архив — AES-256 (pyzipper), пароль — фраза не короче 20 знаков,
  программа её не хранит; писать можно только на том, что владелец один раз отметил доверенным по серийному
  номеру тома (диск с Windows и диск с программой — никогда).
- **Две службы, читающие секреты друг друга.** У каждой свой пакет в
  `%PROGRAMDATA%\PW_STORAGE_SERVICE_<profile>_<NAME>`: ACL «только её SID» и TPM-ключ, запечатанный под этот
  же SID. Отзыв (`revoke`) заменяет значения пустым списком и флагом «разрешение отозвано».

## От чего это не защищает

Честный список — он же список того, что нужно закрывать другими средствами:

- **Процесс той же учётной записи, пока хранилище открыто.** Он может обратиться к каналу и получить
  одобренные проекту строки. Идентичность по процессу — защита от ошибки и от случайного путания проектов,
  не от злого кода той же учётки. Настоящая граница возможна только снаружи: отдельная учётная запись
  Windows (со своим экземпляром PW_STORAGE) под классы задач, которым нельзя доверять на одном ПК.
- **Процесс той же учётной записи без пароля видит перечень.** `preview` отдаётся по одному факту, что
  проект лежит внутри `projects_root`: номера строк, комментарии и признак `ALL` — без пароля и без
  подтверждения. Это осознанный компромисс: иначе окно не покажет, что именно просят. **Поэтому в
  комментариях не пишут то, что само по себе секрет** («пароль от админки банка — 2024») — комментарий
  предназначен для «токен поиска», «логин кабинета оператора».
- **Клавиатурный шпион и снимок экрана.** Пароль, код и значения проходят через окно и память процесса;
  программа их не прячет от того, кто читает ввод или память твоего же пользователя.
- **Физический доступ к разблокированной сессии.** Кто сел за твой ПК — тот и владелец в глазах системы.
- **Компрометация Telegram-аккаунта.** Подтверждение кнопками — это «телефон у тебя в руках». Угнанный чат с
  ботом позволяет одобрять строки; сам пароль хранилища боту не сообщается, и канал подтверждений можно
  выключить (`settings.json → "telegram": false`).
- **Подбор удалённого кода и файла восстановления.** Счётчики попыток (`5` в окне, `3` внутри TPM) мешают
  перебирать через программу, но `recovery.json` перебирают офлайн: стойкость — за длиной ответа (минимум
  20 знаков) и за отдельно хранимой частью ключа, которой на диске нет.
- **Полная потеря.** Забыли пароль, ответ на вопрос и часть ключа — восстановить нечем; это цена схемы без
  «мастер-ключа поддержки». Резервная копия файла — единственное, что возвращает доступ к значениям.
- **Сам владелец.** Программа мешает ошибиться, а не запретить; `--force` здесь нет и быть не должно.

## Криптография и параметры

| Где | Параметр | Значение |
|---|---|---|
| `vault.kdbx` | формат / KDF | KDBX 4.0, Argon2id |
| | память / проходы / параллелизм | 1024 МиБ / 4 / 4 |
| `recovery.json` | вывод ключа | Argon2id (ответ + часть ключа), 1024 МиБ / 4 / 4 |
| | шифр | AES-256-GCM, AAD — заголовок файла |
| | минимальная длина ответа | 20 знаков |
| | часть ключа | 160 бит, 32 знака Base32 группами по 4 |
| архив выгрузки | шифр | AES-256 (pyzipper), пароль не короче 20 знаков |
| TPM | провайдер | Microsoft Platform Crypto Provider, ключи не извлекаемы |
| каталог | привязка | ключ TPM этого ПК + SHA-256 файла хранилища |
| пакеты служб | привязка | машинный ключ TPM + SID `NT SERVICE\<NAME>` + ACL каталога |
| удалённый код | формат | цифры, не короче 8 (`MIN_CODE_DIGITS`) |

## Ограничения попыток и ожидания

| Константа | Значение | Что отсекает |
|---|---|---|
| `MAX_PASSWORD_ATTEMPTS` | 5 | перебор пароля хранилища через окно |
| `MAX_CODE_ATTEMPTS` | 5 | перебор кода из приложения-аутентификатора в окне доступа: после пяти запрос отклоняется |
| `MAX_REMOTE_ATTEMPTS` | 3 | TPM сам блокирует ключ после неверных кодов — останавливаемся раньше |
| `CONFIRM_SECONDS` | 180 | время жизни кнопок в Telegram |
| `OPEN_WAIT_SECONDS` | `CONFIRM_SECONDS` + 900 | сколько клиент ждёт решения владельца |
| `IDLE_EXIT_SECONDS` | 600 | посредник без доступа завершается и отпускает файл |
| `MAX_WHY_CHARS` | 300 | длина причины запроса |
| `MAX_REQUEST_BYTES` / `MAX_REQUEST_ROWS` | 64 КиБ / 200 | размер запроса к каналу |
| `STALE_DAYS` | 45 | «давно не брали» в чистках |

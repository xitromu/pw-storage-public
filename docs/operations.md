# Эксплуатация

Здесь — повседневные действия владельца. Установка и первый запуск в [install.md](install.md),
устройство системы в [architecture.md](architecture.md), почему так, а не иначе —
в [security-model.md](security-model.md).

## Меню владельца

`pw_menu.bat` (боевой профиль) или `pw_menu.bat --profile test`. Пункты:

| Клавиша | Что | Комментарий |
|---|---|---|
| `N` | Создать хранилище | пароль, контрольный вопрос, код TOTP |
| `1` | Окно управления | матрица «записи × проекты», чистки, подключение проектов |
| `2` | Добавить секрет | значение вводится в окне, не в файле и не в чате |
| `3` | Выгрузка | зашифрованный архив на доверенный носитель |
| `4` | Сменить пароль | старый пароль и новый |
| `5` | Новая часть ключа | часть ключа восстановления утеряна или сменилось место |
| `6` | Забыл пароль | понадобится ответ на вопрос и часть ключа из надёжного места |
| `7` | Код доступа | код для доступа через бота, когда вас нет у ПК |
| `8` | Пакеты службам | перевыпустить секреты служб из их конфигураций и перезапустить их |
| `9` | Посредник | запуск доступа проектам; `Ctrl-C` или закрытие окна останавливает |
| `H` | Справка | полный список команд обслуживания |

Те же действия доступны командами `python -m pw_storage.admin …` и окнами напрямую. Пункт `8` и работа со
службами требуют администратора: меню само поднимает окно с UAC.

## Повседневная выдача

1. Проект просит строки: `python <путь>\pw.py open --why "зачем" 1a2b3c4d 9f8e7d6c` (номера — из
   `pw.py list`).
2. Посредник показывает окно: проект, сессия, причина запроса и матрицу строк с отметками. Отметь лишнее —
   оно уйдёт из одобрения.
3. Подтверди срок (по умолчанию `grant_hours`) и способ: окно, кнопка в Telegram или код из
   приложения-аутентификатора.
4. Если строка из `ALL`, одобрение добавляет проект в список записи этой строки — в следующий раз она будет
   в его «своих».

Отозвать всё сразу: `pw.py close` (работает на весь проект, включая другие его сессии — не вызывай её в
конце каждого скрипта). Посредник без активных доступов закрывается сам через 10 минут и отпускает файл.

## Новая строка

Окно «Новая запись» (пункт `2` или кнопка в окне «Проекты»): проект(ы), сервис, имя ключа, значение,
комментарий. Правила:

- **Комментарий обязателен по смыслу**: строки без комментария не выдаются вовсе, а по нему владелец
  понимает, что просят.
- Имена `сервис / ключ` уникальны в пределах проекта — иначе `get` ответит `ambiguous`.
- `ALL` ставь только тем строкам, которые действительно могут понадобиться другому проекту.
- Значения `_SYSTEM` (TOTP, часть ключа) программные; руками их не правят.

## Забытый пароль

`recovery.json` + ответ на контрольный вопрос + часть ключа, которую ты держишь в другом месте. Пункт `6`:

1. Программа покажет вопрос (он лежит в файле открытым текстом — иначе окно не смогло бы его показать).
2. Введёшь ответ и часть ключа → получишь возможность задать новый пароль.

Счётчик попыток относится к окну: сам файл перебирают вне программы, поэтому стойкость держится на длине
ответа (минимум 20 знаков) и на части ключа, которой на диске нет. Если часть ключа утеряла — пункт `5`
(`reissue`): старым паролем выдаётся новая часть, старая перестаёт действовать.

Если потеряны пароль, ответ и часть ключа — восстановить нечем. Это осознанная цена схемы без мастер-ключа:
остаётся резервная копия `vault.kdbx` и выгрузка на носитель.

## Смена пароля и ротация

Пункт `4` (`passwd`) меняет пароль хранилища и собирает новый файл восстановления с новой частью ключа.
Файл `vault.kdbx.bak` и старый `remote.bin` при этом убираются. Действующие доступы проектов не сбрасываются:
пароль нужен для входа в посредник, а не для каждой выдачи.

## Доступ без ПК

- **Подтверждения в Telegram** (пункт меню `admin telegram on|off`, в боевом профиле включено по умолчанию).
  Нужны ровно две строки с меткой проекта `COMMON`: `TG_BOT_TOKEN` (токен своего бота от @BotFather) и
  `TG_CHAT_ID` (твой chat id). Значений на диске нет — посредник читает их из хранилища после ввода пароля.
  Кнопки живут 180 секунд, потом решает окно. Если тот же бот опрашивается ещё где-то, укажи в
  `settings.json` файл-запрет `telegram_queue_lock`: два поллера одной очереди недопустимы.
- **Код доступа вместо пароля** (пункт `7`). Отдельный код (цифры, не короче 8) запечатывает пароль в
  `remote.bin` ключом TPM. С него начинается вход через бота, когда ты не у компьютера. Не путай с кодом
  TOTP из приложения-аутентификатора — тот подтверждает выбор строк.

## Выгрузка на носитель

Пункт `3`. Архив zip с AES-256 собирается в памяти и пишется сразу на носитель: временных файлов с
открытыми значениями нет ни на ПК, ни на флэшке. Внутри — папка `PW_STORAGE`: файл-каталог со всеми
записями (включая часть ключа восстановления) и папки проектов с вложениями. Носитель предварительно
помечается доверенным по серийному номеру тома (`trusted_media` в `settings.json`); диск с Windows или с
программой не подойдёт никогда.

**Обратно в программу архив не читается** — это копия на случай потери файла или переезда на другой ПК:
значения восстанавливают вручную (файл открывается KeePassXC, содержимое заводят заново окнами).

## Чистки

Окно управления (пункт `1`) знает, кто и что брал, и предлагает убрать лишнее:

- строки без комментария — их нельзя запросить;
- строки, которые не брали дольше `STALE_DAYS` (45 дней);
- проекты, которые числятся в списке записи, но доступ не запрашивали;
- забытые открытые файлы секретов в проектах — программа их показывает, сама не читает и не удаляет.

Удалённое уходит в корзину внутри файла хранилища: в перечень и выдачу не попадает, в выгрузку на носитель —
да. Окончательно — «Очистить корзину».

## Службы без человека

Постоянный процесс не может дождаться, пока владелец подтвердит строки, поэтому у него отдельный путь:
свой пакет секретов, привязанный к его учётной записи Windows. Держать в курсе посредника нельзя — иначе
секреты окажутся в каталоге общего доступа.

Обозначения: `PW_MYBOT` — имя службы (только `PW_…`), `MYBOT` — проект, `C:\projects\MYBOT` — его папка.

### 1. Строки в хранилище

Заведи нужные значения окном «Новая запись» с меткой проекта `MYBOT` и пометкой `ALL` — иначе `service_store`
их не увидит. Запомни номер строки (`pw.py list` в папке проекта).

### 2. Манифест пакета

`deploy\services\mybot.json` — реестр без значений:

```json
{
  "name": "PW_MYBOT",
  "profile": "main",
  "bindings": [
    {"project": "MYBOT", "row": "1a2b3c4d", "service": "Telegram", "key": "BOT_TOKEN", "alias": "BOT_TOKEN"}
  ]
}
```

`alias` — имя, под которым секрет придёт в скрипт. Образцы: `deploy\services\demo_bot.example.json`.

### 3. Конфигурация процесса

`deploy\services\mybot.launch.json` — что запускать (полей ровно пять):

```json
{
  "name": "PW_MYBOT",
  "profile": "main",
  "argv": ["C:\\projects\\MYBOT\\.venv\\Scripts\\python.exe", "-X", "utf8", "C:\\projects\\MYBOT\\bot.py", "--service"],
  "cwd": "C:\\projects\\MYBOT",
  "log": "C:\\ProgramData\\PW_STORAGE_LOGS\\PW_MYBOT\\service.log"
}
```

`log` должен совпадать с путём, который программа сама выделяет службе, иначе `install` откажет.

### 4. Регистрация и выдача пакета

Всё вместе делает `provision_services.bat` (или меню, пункт `8`) — он же перезапускает службу:

```bat
provision_services.bat deploy\services\mybot.json
```

Что происходит под капотом (нужен администратор):

```bat
.venv\Scripts\python.exe -m pw_storage.service_store provision deploy\services\mybot.json --apply
.venv\Scripts\python.exe -m pw_storage.service_host install --name PW_MYBOT --config deploy\services\mybot.launch.json --apply
.venv\Scripts\python.exe -m pw_storage.service_host start --name PW_MYBOT --apply
.venv\Scripts\python.exe -m pw_storage.service_host status --name PW_MYBOT
```

Пакет ложится в `%PROGRAMDATA%\PW_STORAGE_SERVICE_main_PW_MYBOT\credentials.bin`: ACL — только
`NT SERVICE\PW_MYBOT`, TPM-ключ запечатан под её же SID.

### 5. Чтение в скрипте службы

```python
from pw_storage.service_store import ServiceClient

token = ServiceClient("PW_MYBOT").get("BOT_TOKEN")
```

`get` работает только из процесса этой службы: другая учётная запись получит «Служебные секреты недоступны».
В stderr печатается имя взятого ключа (в журнал идёт то же), значение — никогда.

Если служба не может прочитать свой `.venv` (такое бывает, когда пакеты в него жёстко ссылуются с ACL кэша),
дай право чтения кода:

```bat
grant_service_read.bat PW_MYBOT C:\projects\MYBOT\.venv
```

### Смена значений и отзыв

- Изменил секрет в хранилище → перевыпусти пакет и перезапусти: `provision_services.bat` снова или пункт `8`
  меню (всех служб разом — если запускать его без аргумента, он обойдёт все конфигурации из
  `deploy\services\`).
- Отзыв: `python -m pw_storage.service_store revoke PW_MYBOT --profile main --apply` — вместо значений в
  пакете остаётся пустой список и флаг «разрешение отозвано»; служба дальше работать со старыми секретами не
  сможет. Удаление службы — `service_host uninstall --name PW_MYBOT --apply`, потом `revoke`.

## Диагностика

| Симптом | Что смотреть |
|---|---|
| «Посредник не запущен» | `pw.py status`; запусти посредник (пункт `9`) — при `open` он поднимется сам |
| `project_unknown` | команда запущена вне `projects_root`; проверь `projects_root` в `data\settings.json` |
| `needs_access` / `not_approved` | срок вышел или строка менялась после одобрения: `pw.py list` → новый `open` |
| `no_catalog` | перечень не собран: `pw.py open --why "собрать перечень"` без номеров, владелец введёт пароль |
| `vault_pending` | есть незавершённая запись (`.transaction`): доверь её дорешать программе, не удаляй файл журнала наугад |
| «неверный пароль» 5 раз | запрос отклоняется намеренно; проверь раскладку и не пытайся подобрать |
| служба стартует и падает | `%PROGRAMDATA%\PW_STORAGE_LOGS\PW_MYBOT\service.log`; после 8 быстрых отказов подряд надзор сдаётся |
| служба не видит секреты | пакет выдан под другую учётную запись? `service_store provision` перезапусти от администратора; проверь `grant_service_read.bat` |
| Telegram молчит | строки `TG_BOT_TOKEN` / `TG_CHAT_ID` с меткой `COMMON`, `"telegram": true`, второй поллер того же бота |
| кнопки не приходят | истёк `CONFIRM_SECONDS` (180 с) — решай в окне; проверь сеть до `api.telegram.org` |

Журнал выдачи — `logs\access.log` (JSON-строки). Значений секретов там не бывает ни при каких обстоятельствах,
так что файл можно показывать и пересылать.

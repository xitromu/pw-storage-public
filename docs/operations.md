# Эксплуатация

Повседневные действия владельца. Начни с [установки](install.md); устройство системы описано в
[архитектуре](architecture.md), границы защиты — в [модели угроз](security-model.md).

## Меню владельца

`pw_menu.bat` — основной профиль; `pw_menu.bat --profile test` — демонстрационный.

| Клавиша | Действие |
|---|---|
| `N` | Создать хранилище: пароль, контрольный вопрос, TOTP |
| `1` | Окно управления: записи, матрица доступа, чистки, подключение проектов |
| `2` | Добавить секрет через окно |
| `3` | Зашифрованная выгрузка на доверенный носитель |
| `4` | Сменить пароль |
| `5` | Перевыпустить часть ключа восстановления |
| `6` | Восстановить пароль по ответу и части ключа |
| `7` | Создать отдельный код удалённого доступа через бота |
| `8` | Перевыпустить пакеты зарегистрированных служб и перезапустить их |
| `9` | Запустить посредника выбранного профиля |
| `H` | Справка |
| `0` | Выйти из меню |

Команды доступны также через `python -m pw_storage.admin …` из окружения хранилища.
Для управления службами нужны права администратора; пункт `8` вызывает UAC.

## Повседневная выдача

1. Из папки проекта выполни `python <путь-к-репозиторию>\pw.py list`.
2. Запроси конкретные номера: `pw.py open --why "операция и получатель" 1a2b3c4d`.
   Здесь и далее `1a2b3c4d` — пример: подставь номер из своего `list`.
3. Владелец выбирает записи и срок, вводит пароль в локальном окне и подтверждает TOTP или настроенным Telegram.
4. Если выбрана запись из `ALL`, проект добавляется в её список; это не выдаёт её остальным проектам автоматически.
5. Скрипт читает одобренные записи через `PwClient().get(service, key)`.

`open` и `preview` запускают посредника при необходимости; `get`, `status` и `report` — нет.
Доступ относится ко всему проекту. Без активных разрешений и запросов посредник завершается через 10 минут.

### Как отозвать доступ

- `pw.py close` **из папки проекта** запрещает его новые чтения и отменяет ожидающие запросы всех его сессий.
- Закрытие окна посредника прекращает новые чтения всех проектов этого посредника.
- **Снятие отметки в другом окне или изменение KDBX внешним редактором не гарантирует немедленный отзыв**
  уже загруженных разрешений. Для немедленного отзыва используй `close` или остановку посредника.
- Уже полученное значение может оставаться в памяти скрипта или в созданных им копиях. Для полного прекращения
  использования останови получателей и при необходимости отзови секрет у провайдера.

Не вызывай `close` автоматически в конце каждого скрипта: это прервёт доступ остальных сессий проекта.

## Новая строка

Пункт `2` или кнопка новой записи в окне «Проекты»: проекты, сервис, имя ключа, значение и комментарий.

- Комментарий нужен для осмысленного одобрения; пустые комментарии не выдаются.
- Не помещай секреты в комментарий, имя ключа, имя проекта или причину запроса: это видимые метаданные.
- Избегай одинаковых `сервис / ключ` у нескольких подходящих записей: неоднозначное чтение вернёт `ambiguous`.
- `ALL` ставь только записям, которые другой проект должен иметь возможность запросить.
- `_SYSTEM` содержит служебные записи TOTP и восстановления; не изменяй их вручную.

## Забытый пароль

Пункт `6` использует `recovery.json`, ответ на контрольный вопрос и отдельно сохранённую часть ключа.
Вопрос лежит в recovery-файле открыто; остальные данные позволяют восстановить пароль и задать новый.

Файл можно подбирать офлайн, поэтому ограничения окна не заменяют стойкий ответ и сохранность части ключа.
Часть также хранится **внутри зашифрованного KDBX** и включается в зашифрованную выгрузку, но при забытом
пароле получить её из закрытого KDBX нельзя. Пункт `5` позволяет перевыпустить часть при известном пароле и ответе.

Если неизвестен пароль и нет подходящих данных восстановления, обычная копия KDBX доступ не вернёт.
Отдельная выгрузка может помочь, только если её пароль известен; записи из неё переносятся вручную.

## Смена пароля и ротация

Пункт `4` меняет пароль текущего KDBX, создаёт новые данные восстановления и убирает локальные
`vault.kdbx.bak` и старый `remote.bin`. Доступы уже работающего посредника автоматически не сбрасываются.

Это не ротация токенов у внешнего сервиса и не изменение уже скопированных файлов.
После компрометации отзывай секреты у провайдеров; порядок описан в [SECURITY.md](../SECURITY.md).

## Доступ без ПК

Telegram необязателен: локальное подтверждение паролем и TOTP работает без него.

Для Telegram нужны две непустые записи с проектом `COMMON`: `TG_BOT_TOKEN` и `TG_CHAT_ID`.
Посредник читает их из зашифрованного KDBX после ввода пароля; отдельный открытый файл с токеном не нужен.
Настройка `telegram` по умолчанию включена для `main`, выключена для `test`.
Переключение из окружения хранилища: `python -m pw_storage.admin telegram on` или `off`.

В Telegram отправляются проект, срок, причина запроса и комментарии записей.
На подтверждение отведено 180 секунд; по истечении времени запрос отклоняется, нужно запросить снова.
Если связь пропала, до окончания времени можно подтвердить TOTP в локальном окне.
Два поллера одного бота недопустимы; `telegram_queue_lock` помогает только при согласованном использовании
файла аренды участниками, а не блокирует любые внешние программы автоматически.

Для входа без локального ввода пароля есть **отдельный режим удалённого кода** (пункт `7`): код от 8 цифр
защищает TPM-ключом пароль в `remote.bin`. Код передаётся через чат и не является TOTP.
Бот пытается удалить сообщение, но полное исчезновение копий не гарантируется.
Подробнее о рисках — в [SECURITY.md](../SECURITY.md#telegram-и-работа-без-сети).

## Выгрузка на носитель

Пункт `3` собирает AES-256 ZIP в памяти и пишет зашифрованный архив сразу на выбранный носитель.
Носитель нужно предварительно отметить доверенным по серийному номеру тома.
Тома с Windows и с программой исключаются. Пароль архива — от 20 знаков; программа его не хранит.

В архиве — `PW_STORAGE/catalog.txt` с записями и частью ключа восстановления, а также вложения.
Имена файлов ZIP видны без пароля. После распаковки каталог содержит открытые значения:
не помещай его в проект, чат, git или обычную папку синхронизации.

**Автоматического импорта нет.** Каталог читается текстовым редактором, а записи при восстановлении
заводятся заново через окна. Это не KDBX-файл для KeePassXC; KeePassXC открывает отдельную копию самого KDBX.

## Чистки

Окно управления предлагает записи без комментария, неиспользуемые записи и лишние связи с проектами.
Порог неиспользования по журналу — 45 дней. Отсутствие события в журнале не доказывает, что секрет
не используется вне PW_STORAGE.

Программа также показывает забытые открытые файлы секретов в проектах, но сама не читает и не удаляет их.
Удалённые записи попадают в корзину KDBX: не выдаются проектам, но входят в выгрузку.
Окончательное удаление — «Очистить корзину»; прежние копии KDBX при этом не очищаются.

## Службы без человека

Постоянный процесс получает отдельный пакет под свою виртуальную учётную запись Windows,
а не интерактивное разрешение посредника. Пример: служба `PW_MYBOT`, проект `MYBOT`.

### 1. Записи и манифест

Заведи записи с проектом `MYBOT` и непустым комментарием. **Пометка `ALL` не требуется**:
проверяются номер записи, членство проекта, сервис и имя ключа.

Скопируй пример `deploy/services/demo_bot.example.json` в `deploy/services/mybot.json`:

```json
{
  "name": "PW_MYBOT",
  "profile": "main",
  "bindings": [
    {"project": "MYBOT", "row": "1a2b3c4d", "service": "Telegram", "key": "BOT_TOKEN", "alias": "BOT_TOKEN"}
  ]
}
```

Подставь реальный номер, но не значение. `alias` — имя чтения из пакета.

### 2. Конфигурация процесса

Скопируй `deploy/services/demo_bot.launch.example.json` в `deploy/services/mybot.launch.json`.
Поля конфигурации:

```json
{
  "name": "PW_MYBOT",
  "profile": "main",
  "argv": ["C:\\projects\\MYBOT\\.venv\\Scripts\\python.exe", "-X", "utf8", "C:\\projects\\MYBOT\\bot.py", "--service"],
  "cwd": "C:\\projects\\MYBOT",
  "log": "C:\\ProgramData\\PW_STORAGE_LOGS\\PW_MYBOT\\service.log"
}
```

`log` должен соответствовать выделенному службе пути в `%PROGRAMDATA%`; на системе с другим расположением
ProgramData скорректируй пример. Реальный скрипт и его зависимости нужно подготовить отдельно.

### 3. Установка и выдача

В **администраторской командной строке**, из папки репозитория:

```bat
.venv\Scripts\python.exe -m pw_storage.service_host install --name PW_MYBOT --config deploy\services\mybot.launch.json --apply
grant_service_read.bat PW_MYBOT C:\projects\MYBOT\.venv
provision_services.bat deploy\services\mybot.json
```

Обёртка `provision_services.bat` **не регистрирует службу**: она выпускает пакет, останавливает уже
зарегистрированную службу, запускает её и показывает статус. Без аргументов обходит реальные манифесты
в `deploy/services/`, исключая `.launch.json` и `.example.json`.

Пакет: `%PROGRAMDATA%\PW_STORAGE_SERVICE_main_PW_MYBOT\credentials.bin`.
Он защищён ACL и машинным TPM-ключом для SID `NT SERVICE\PW_MYBOT`; это не защита от администратора или ядра.

### 4. Чтение в службе

```python
from pw_storage.service_store import ServiceClient

token = ServiceClient("PW_MYBOT").get("BOT_TOKEN")
```

Процесс-получатель работает от учётной записи службы. Чтение пакета не требует окна владельца.
Секрет не печатай; журналы приложения-получателя контролируй отдельно.

### Смена значений и отзыв

Изменение записи в KDBX не обновляет пакет службы автоматически.
Перевыпусти его и перезапусти службу через `provision_services.bat` или пункт `8`.

Отзыв из окружения хранилища, от администратора:

```bat
.venv\Scripts\python.exe -m pw_storage.service_store revoke PW_MYBOT --profile main --apply
.venv\Scripts\python.exe -m pw_storage.service_host stop --name PW_MYBOT --apply
```

`revoke` запрещает **новые чтения пакета**. Уже полученные значения в памяти или копиях не исчезают;
поэтому остановка получателя и ротация у провайдера при компрометации выполняются отдельно.

## Диагностика

| Симптом | Действие |
|---|---|
| `BrokerUnavailable` | `pw.py list` / `open` запускают посредника; сам `get` этого не делает |
| `project_unknown` | запускай команду из проекта внутри настроенного `projects_root` |
| `needs_access` / `not_approved` | `pw.py list` → новый `open` нужных номеров |
| `no_catalog` | `open --why "собрать перечень"` без номеров; владелец введёт пароль, затем повтори `list` |
| `vault_pending` | не удаляй `.transaction` наугад; незавершённая запись требует разбора |
| пять неверных паролей | запрос отклонён; проверь раскладку, не продолжай подбор |
| истекли 180 секунд | запроси доступ заново; для локального TOTP тоже нужен неистёкший запрос |
| служба не стартует | проверь конфигурацию, права на код и журнал службы |
| служба не видит секреты | проверь проект/номер в манифесте, получателя пакета и перевыпуск |
| Telegram молчит | записи `TG_BOT_TOKEN` / `TG_CHAT_ID`, настройка `telegram`, сеть и отсутствие другого поллера |

`logs/access.log` содержит метаданные, включая причины запросов и пути.
Перед пересылкой проверь и обезличь его: приложение не гарантирует, что пользователь не вписал секрет
в комментарий, имя ключа или причину запроса.

# Подключение проекта

Две ситуации: проект новый и проект, у которого секреты уже лежат в файлах. В обоих случаях программа
работает так: агент видит номера строк и комментарии, но значения получают только те процессы, которым они
нужны для дела.

## Блок в `CLAUDE.md`

Окно «Проекты» (пункт `1` меню → кнопка «Подключить проект») показывает текст и пишет его между метками
`<!-- PW_STORAGE: начало -->` / `<!-- PW_STORAGE: конец -->`. Повторная запись заменяет блок, остальной файл
не трогается; кодировка и переводы строк сохраняются. Выглядит так (путь — к копии этого репозитория):

```markdown
## Секреты
- Секреты проекта — только в хранилище PW_STORAGE. Не заводить secrets.env, .env, пароли в коде и в git.
- Что есть: python C:\projects\PW_STORAGE\pw.py list — номера строк и комментарии, без значений.
- Доступ для всего проекта на срок: pw.py open --why "зачем" <номера> — владелец подтверждает выбранные строки в окне; разрешение общее для всех сессий проекта.
- pw.py close закрывает доступ всему проекту и отменяет его ожидающие запросы.
- В скриптах: PwClient().get("сервис", "ключ"). Значения не печатать и не писать в файлы, журналы, чат.
- Нужен новый секрет — попросить владельца завести его в окне «Новая запись».
```

Сам блок короткий: он нужен агенту в каждый момент работы. Правила подробнее — ниже и в
[security-model.md](security-model.md); в проекте их стоит держать в голове целиком:

- Проект определяет посредник по процессу и рабочей папке. Проектные команды запускай из папки проекта;
  не выдавай себя за другой проект.
- Не открывай файлы хранилища, чужие файлы секретов и резервные копии. Работай через клиент.
- Значения не выводятся в чат, stdout, журналы, аргументы команд, документацию и git. Получатель — память
  того процесса, которому секрет нужен.
- Если секрет недоступен — останови операцию и запроси доступ, а не обходи подтверждение и не лезь в старый
  файл «как запасной».
- Разрешение на строки не разрешает внешние действия: отправку сообщений, покупку, публикацию, запись в
  оборудование.
- `close` отзывает доступ всему проекту, включая другие сессии. Не вызывай её в конце каждого скрипта.

## Новый проект

1. Заполни реестр нужных секретов — именами и назначениями, без значений.
2. Посмотри перечень: `python <PW_STORAGE>\pw.py list`. Возможно, подходящая строка уже есть у кого-то из
   `ALL` — не плоди дубль и не расширяй права проектов без согласия владельца.
3. Если записи нет — попроси владельца завести её в окне «Новая запись» и указать этот проект. Значения
   владелец вводит в окно, не в чат и не в файл.
4. Запроси доступ: `pw.py open --why "конкретная операция и процесс-получатель" <номера>`.
5. Проверь поведение без доступа (`NeedsAccess`) и после подтверждения. Первую пробу делай без внешних
   действий и без печати значений.

## Старый проект

1. Найди места загрузки секретов, не читая значений. Заполни реестр именами и назначениями.
2. Сопоставь со строками хранилища. Не выбирай строку только по похожему комментарию: сомнение — к владельцу.
3. Замени чтение файлов секретов на клиент `PW_STORAGE`. Пусть скрипт берёт ровно те строки, которые нужны
   для операции.
4. Проверь отказ без доступа и работу после подтверждения.
5. Файлы секретов владелец убирает из проекта или разрешает перенести в точно указанное резервное место.
   Переименование внутри проекта файл от поиска не прячет; удаление — только после приёмки и отдельного
   согласия.

## Реестр секретов проекта

Веди таблицу в `CLAUDE.md` проекта или рядом — только метаданные. При неизвестном номере или соответствии
пиши «требует согласования».

| Назначение | Процесс-получатель | Сервис | Имя ключа | Номер строки | Состояние |
|---|---|---|---|---|---|
| Example: выгрузка отчёта | `report.py` | `Погода` | `API_KEY` | `1a2b3c4d` | подключено |

Значений, отпечатков значений, паролей, кодов подтверждения и содержимого вложений здесь быть не должно.

## Команды

```bat
python <PW_STORAGE>\pw.py list
python <PW_STORAGE>\pw.py open 1a2b3c4d 9f8e7d6c --why "Собрать отчёт за ноябрь, получатель report.py"
python <PW_STORAGE>\pw.py status
python <PW_STORAGE>\pw.py report
python <PW_STORAGE>\pw.py close
```

`pw.py` — единственная точка, где решение принимает человек: команда печати значения отсутствует в интерфейсе
намеренно. Номера строк идут перед параметрами, `--why` обязателен (его видит владелец в окне и в Telegram).

## Клиент в скрипте

```python
import sys

sys.path.insert(0, r"C:\projects\PW_STORAGE")     # путь к копии этого репозитория
from pw_storage.client import NeedsAccess, NotFound, PwClient

pw = PwClient(profile="main")                      # посредник поднимется сам
try:
    token = pw.get("Погода", "API_KEY")
except NeedsAccess:
    ...               # строки нет в одобренных: pw.py list → pw.py open --why "зачем" <номера>
except NotFound:
    ...               # такой записи у проекта нет
```

| Метод | Что делает |
|---|---|
| `get(service, key)` | значение одобренной строки; при нескольких подходящих — `PwError` (`ambiguous`) |
| `get_attachment(service, key, name)` | вложение в память байтами, без записи на диск |
| `save_token(service, key, value, expected=…)` | заменяет значение, только если текущее совпало с `expected`; доступ не продлевает |
| `rows()` | одобренные строки: номер, сервис, имя ключа, комментарий, признак `ALL`. Значений нет |
| `report()` | какие ключи проект уже взял |
| `open(rows, why)` / `status()` / `close()` | то же, что команды `pw.py` |

Исключения: `PwError` и частные `NeedsAccess`, `NotFound`, `BrokerUnavailable`, `ProjectUnknown`,
`TokenConflict`. Клиенту нужен только стандартный Python 3.10+ — он не тянет зависимости хранилища, поэтому
подходит для виртуального окружения проекта.

В stderr клиент печатает имя взятого ключа (`[PW_STORAGE] взят ключ: Погода / API_KEY (строка 1a2b3c4d)`) —
это намеренно: след покупки виден в логе процесса, а значения нет.

Если инструмент требует файл (keystore, `.p12`, конфиг), отдельно согласуй с владельцем временное размещение
и очистку: `get_attachment` возвращает байты, и ответственность за то, куда они лягут, остаётся на скрипте.

## Служба вместо скрипта

Постоянный процесс, который не может дождаться подтверждения, живёт по другим правилам: свой пакет секретов,
своя учётная запись Windows, чтение через `ServiceClient`. Порядок —
в [operations.md](operations.md#службы-без-человека).

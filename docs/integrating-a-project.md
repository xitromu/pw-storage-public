# Подключение проекта

Цель — заменить копии секретов в файлах проекта управляемым чтением через Python-клиент.
Агент работает с метаданными и запросами, а значение получает выполняемый скрипт.
Это правило рабочего процесса, а не изоляция недоверенного кода одной учётной записи.

## Инструкции в `AGENTS.md`

Окно «Проекты» показывает блок правил и после «Записать» добавляет его в `AGENTS.md` выбранного проекта.
Повторная запись заменяет только текст между метками `<!-- PW_STORAGE: начало -->` и
`<!-- PW_STORAGE: конец -->`; остальные инструкции, BOM и переводы строк сохраняются.

Пример для установки в `C:\projects\pw-storage-public`:

```markdown
## Секреты
- Секреты проекта — только в хранилище PW_STORAGE. Не заводить secrets.env, .env, пароли в коде и в git.
- Что есть: "C:\projects\pw-storage-public\.venv\Scripts\python.exe" "C:\projects\pw-storage-public\pw.py" list — номера строк и комментарии, без значений.
- Доступ для всего проекта на срок: "C:\projects\pw-storage-public\.venv\Scripts\python.exe" "C:\projects\pw-storage-public\pw.py" open --why "зачем" НОМЕР_СТРОКИ — подставить нужные номера из list; владелец подтверждает выбранные строки в окне.
- "C:\projects\pw-storage-public\.venv\Scripts\python.exe" "C:\projects\pw-storage-public\pw.py" close закрывает доступ всему проекту и отменяет его ожидающие запросы.
- В скриптах: PwClient().get("сервис", "ключ"). Значения не печатать и не писать в файлы, журналы, чат.
- Нужен новый секрет — попросить владельца завести его в окне «Новая запись».
```

**Подключи файл к своему ассистенту.** Не каждый инструмент автоматически читает `AGENTS.md`.
Если ассистент использует собственный файл или настройку инструкций, подключи `AGENTS.md` через
поддерживаемый этим инструментом импорт или явное указание. Идентификатор сессии не означает, что правила загружены.

Если проект подключался прежней версией через `CLAUDE.md`, перенеси блок в `AGENTS.md` вручную,
сохранив остальные инструкции. Программа не переименовывает старые файлы и не объединяет их автоматически.

## Новый проект

1. Создай папку проекта внутри `projects_root` (по умолчанию `C:\projects`), например `C:\projects\REPORT`.
2. Запусти меню владельца `pw_menu.bat`, создай основное хранилище и добавь запись для проекта `REPORT`.
   Укажи сервис, имя ключа, значение и понятный комментарий. Значение вводи только в окно.
3. Если подходящая запись уже помечена `ALL`, проект может запросить её; копию создавать не нужно.
4. Выполни команды ниже из папки проекта и подтверди выбранные записи.
5. Подключи клиент к своему скрипту. Первую проверку делай без внешних действий и печати значений.

## Старый проект

1. Найди места загрузки секретов и заполни реестр их имён и назначений, без значений.
2. Сопоставь их с конкретными записями хранилища; одного похожего комментария недостаточно.
3. Замени чтение файлов на `PwClient().get(...)` и проверь отказ без доступа и чтение после подтверждения.
4. Только после проверки убери прежние файлы секретов с согласия владельца.
5. Если значения уже попадали в git или другую копию, удаление файла из рабочей папки не отзывает их:
   замени секреты у провайдеров и разберись с прежними копиями отдельно.

## Реестр без значений

| Назначение | Получатель | Сервис | Ключ | Номер | Состояние |
|---|---|---|---|---|---|
| Данные погоды для отчёта | `report.py` | `Погода` | `API_KEY` | `1a2b3c4d` | пример; подставить свою запись |

Не включай значения, их отпечатки, пароли, TOTP, удалённые коды или содержимое вложений.
Неизвестное соответствие помечай «требует согласования».

## Команды

Для **Windows Command Prompt (`cmd.exe`)**. Если установил репозиторий в другую папку, замени оба пути.
`1a2b3c4d` ниже — пример: подставь номер своей записи из `list`.

```bat
cd /d C:\projects\REPORT
"C:\projects\pw-storage-public\.venv\Scripts\python.exe" "C:\projects\pw-storage-public\pw.py" list
"C:\projects\pw-storage-public\.venv\Scripts\python.exe" "C:\projects\pw-storage-public\pw.py" open --why "Собрать отчёт, получатель report.py" 1a2b3c4d
"C:\projects\pw-storage-public\.venv\Scripts\python.exe" "C:\projects\pw-storage-public\pw.py" status
"C:\projects\pw-storage-public\.venv\Scripts\python.exe" "C:\projects\pw-storage-public\pw.py" report
```

Для отзыва новых чтений **всего проекта**, включая другие сессии, отдельно выполни:

```bat
"C:\projects\pw-storage-public\.venv\Scripts\python.exe" "C:\projects\pw-storage-public\pw.py" close
```

`--why` обязателен для `open`; его видят окно, журнал и настроенный Telegram.
Причина запроса должна объяснять операцию, но не содержать секретов.
`list` использует `preview` и при необходимости запускает посредника, как и `open`.
`get`, `status`, `report` и `close` не запускают его автоматически.

## Клиент в скрипте

Запускай скрипт из своего проекта после одобрения нужных записей:

```python
import sys

sys.path.insert(0, r"C:\projects\pw-storage-public")
from pw_storage.client import BrokerUnavailable, NeedsAccess, NotFound, PwClient

try:
    token = PwClient(profile="main").get("Погода", "API_KEY")
except (BrokerUnavailable, NeedsAccess, NotFound) as error:
    raise SystemExit(f"Нужен доступ к записи: {error}") from None
```

Дальше передай `token` клиенту своего API. Не выводи его, не записывай в файлы, журналы или чат,
не передавай в аргументах команд. Клиент работает со стандартной библиотекой Python 3.10+;
зависимости хранилища остаются в его окружении Python 3.11+.

| Метод | Результат |
|---|---|
| `get(service, key)` | строковое значение одобренной записи |
| `get_attachment(service, key, name)` | байты вложения в память; временный файл не создаётся |
| `save_token(service, key, value, expected=…)` | замена только при совпадении прежнего значения; срок не продлевает |
| `rows()` | одобренные номера, сервисы, имена ключей и комментарии; без значений |
| `preview()` | доступные для запроса номера и комментарии; запускает посредника при необходимости |
| `open(rows, why)` | запрос выбранных записей владельцу |
| `status()` / `report()` / `close()` | срок, метаданные чтений, отзыв новых чтений проекта |

Исключения: `PwError`, `NeedsAccess`, `NotFound`, `BrokerUnavailable`, `ProjectUnknown`, `TokenConflict`.
При неоднозначном имени записи чтение возвращает `PwError` (`ambiguous`).
Штатный stderr клиента показывает имя прочитанного ключа, но не значение.

## Правила безопасности интеграции

- Проект определяется по процессу и рабочей папке; это не изоляция вредоноса с твоими правами.
- Правила `AGENTS.md` не препятствуют ассистенту технически; проверь, что он их использует.
- Если доступа нет, запроси его, а не читай прежний файл в качестве обхода.
- Разрешение на чтение секрета не разрешает автоматически внешние действия: публикацию, покупку или запись в устройство.
- Отзыв/истечение срока не удаляет значения из памяти получивших их процессов.
- Если инструмент требует файл вместо байтов, согласуй временное размещение и очистку отдельно:
  ответственность за файл несёт интеграция, не `get_attachment`.

## Постоянная служба

Службе или боту без интерактивного окна нужен собственный TPM-пакет и учётная запись Windows.
Порядок: [службы без человека](operations.md#службы-без-человека).
Смена записи в KDBX не обновляет пакет автоматически; нужен его перевыпуск и перезапуск процесса.

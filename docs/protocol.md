# Протокол канала

Описание для тех, кому мало `PwClient`: кому-то нужен другой язык, кому-то — отладка. Клиент тонкий, и
весь смысл здесь в том, что посредник ничего не определяет со слов запроса.

## Транспорт

- Именованный канал Windows: `\\.\pipe\pw_storage` для профиля `main`, `\\.\pipe\pw_storage_test` для `test`.
- Одно соединение = один запрос и один ответ. Соединение закрывается сразу после ответа.
- Сообщения — JSON в UTF-8, переданный `send_bytes` / `recv_bytes` из `multiprocessing.connection`
  (фрейминг с length-prefix и служебными частями). Проще всего писать клиент на том же
  `multiprocessing.connection`: свои разборщики заголовков не нужны.
- Запрос не больше `MAX_REQUEST_BYTES` = 64 КиБ, строк в `open` — не больше `MAX_REQUEST_ROWS` = 200.
- Отдельного пароля у канала нет: его создаёт посредник с правами по умолчанию, поэтому подключиться может
  процесс того же пользователя (и администратор). Роль аутентификации играет не секрет в запросе, а
  определение процесса на другом конце — см. ниже.
- Пустое соединение (клиент подключился и сразу закрыл) — проверка «посредник жив»; на неё посредник
  отвечает молча.

## Идентификация

В запросе нет поля «проект». Посредник берёт pid обращённого процесса из канала и сам определяет
(`procinfo.py`):

- **project** — первая папка под `projects_root`: сначала по пути скрипта, затем по рабочей папке;
- **session** — ближайший предок `claude.exe`, иначе `manual`.

Если процесс и рабочая папка вне корня проектов, ответ один: `project_unknown`. Поэтому подделать чужой
проект можно только запустившись из его папки — то есть будучи им.

## Ответы

Успех: `{"ok": true, …}`. Отказ: `{"ok": false, "error": "<код>", "message": "<по-русски>"}`.
`message` человекочитаемый и безопасный: значений секретов в ответах ошибок не бывает.

| `error` | Когда | Исключение клиента |
|---|---|---|
| `bad_request` | не объект JSON, неизвестная команда, поля не тех типов | `PwError` |
| `project_unknown` | скрипт и рабочая папка вне `projects_root` | `ProjectUnknown` |
| `needs_access` | у проекта нет доступа (или нет одобрения на эту строку) | `NeedsAccess` |
| `not_approved` | строка есть, но её нет в подтверждённом списке либо она изменилась | `NeedsAccess` |
| `not_found` | у проекта нет такой записи / нет такого вложения | `NotFound` |
| `unknown_rows` | запрошен номер, которого проект не видит | `NotFound` |
| `ambiguous` | под `сервис/имя` подходит несколько одобренных строк | `PwError` |
| `ambiguous_attachment` | у строки несколько вложений с одним именем | `PwError` |
| `no_vault` | хранилище ещё не создано | `PwError` |
| `no_catalog` | перечня нет на этом ПК, а номера строк уже указаны | `PwError` |
| `no_rows` | `open` без номеров, хотя перечень есть | `PwError` |
| `vault_pending` | незавершённая запись хранилища требует разбора | `PwError` |
| `timeout` | владелец не ответил за `OPEN_WAIT_SECONDS` (подтверждение + ввод пароля) | `PwError` |
| `denied` | владелец нажал «Отклонить» или отказал по другой причине | `PwError` |
| `token_conflict` | прежнее значение токена не совпало с текущим | `TokenConflict` |
| `vault_busy` | `save_token` пришёл, пока ждётся подтверждение доступа | `PwError` |
| `vault_changed`, `save_failed` | запись токена не удалась | `PwError` |

Клиент бросает `BrokerUnavailable`, если канала нет (посредник не запущен) или он не ответил. Посредник
поднимается сам только там, где нужен владелец: `open` и `preview` (новое консольное окно, в нём видно, что
происходит). `status`, `list`, `get`, `get_attachment`, `save_token`, `report`, `close` требуют, чтобы
посредник уже работал: чтение секрета не должно тайком запускать процесс, о котором владелец не знает.

## Операции

### `status` — есть ли доступ

Запрос: `{"op": "status"}`
Ответ: `{"ok": true, "project": "BETA", "session": "manual", "granted": true, "expires": "2026-11-23T08:12:00"}`
(`expires: null`, когда доступа нет).

### `preview` — что можно запросить

Запрос: `{"op": "preview"}`
Ответ:

```json
{"ok": true, "project": "BETA", "state": "fresh",
 "own": [{"id": "1a2b3c4d", "comment": "Токен сервиса доставки", "all": false}],
 "common": [{"id": "9f8e7d6c", "comment": "Общий токен аналитики", "all": true}],
 "unnamed": 3}
```

Имен ключей, сервисов и значений здесь нет — только номера и комментарии, как в окне до пароля.
`own` — строки с меткой этого проекта, `common` — из `ALL` (одобрение добавит проект в список записи).
`state`: `fresh` / `stale` / `missing`. `unnamed` — число строк без комментария: они не выдаются, пока
владелец не подпишет их. Список проектов, которым принадлежит запись, намеренно не раскрывается.

### `list` — что уже одобрено

Запрос: `{"op": "list"}`
Ответ: `{"ok": true, "rows": [{"id": "…", "service": "Такси", "key": "login", "comment": "…", "all": false}]}`
Без доступа — `needs_access`. По этому ответу скрипт и выбирает, что просить: он видит имена разрешённых
ключей, но не значения. `all: true` — строка пришла из `ALL`.

### `open` — запросить строки

Запрос: `{"op": "open", "rows": ["1a2b3c4d"], "why": "Выгрузить отчёт за ноябрь"}`

- `rows` — номера из `preview`/`list`; пустой список допустим только когда перечня нет: тогда владелец
  соберёт его паролем, доступ не выдаётся.
- `why` — до `MAX_WHY_CHARS` = 300 знаков, видит владелец в окне и в Telegram.

Посредник ставит запрос в очередь и показывает окно (и, если включено, кнопки в боте). Ответ приходит
после решения владельца:

`{"ok": true, "project": "BETA", "granted": true, "expires": "…", "rows": ["1a2b3c4d"]}`

`rows` в ответе — одобренные номера: владелец мог снять часть отметок. Отказ — `denied` с причиной;
нет ответа — `timeout`. Повторный `open` на строки, которые уже одобрены и не менялись, окна не требует:
приходит текущий `status`.

### `get` — получить значение

Запрос: `{"op": "get", "service": "Такси", "key": "login"}`
Ответ: `{"ok": true, "value": "…", "id": "1a2b3c4d"}`

Строка ищется среди видимых проекту и одобренных. Если подходящих несколько, приоритет у записей, чья
группа — сам проект; если и их несколько — `ambiguous`. Если запись изменилась после подтверждения,
одобрение по «штампу» не совпадает и ответ `not_approved`: нужен новый `open`.

### `get_attachment` — вложение

Запрос: `{"op": "get_attachment", "service": "…", "key": "…", "name": "app.keystore"}`
Ответ: `{"ok": true, "id": "…", "data": "<base64>"}`

### `save_token` — вернуть обновлённый токен

Запрос: `{"op": "save_token", "service": "…", "key": "…", "value": "<новый>", "expected": "<старый>"}`
Ответ: `{"ok": true, "id": "…", "warnings": []}`

Заменяет значение одобренной строки, не продлевая доступ. `expected` обязателен: если к этому моменту
значение изменилось, приходит `token_conflict`, и скрипт обязан перечитать токен. При записи обновляется
«штамп» строки в одобрении проекта, так что скрипт продолжает работать. `warnings` — случаи, когда токен
записан, но сопутствующее действие (каталог, журнал) не удалось.

### `report` — что проект уже брал

Запрос: `{"op": "report"}`
Ответ: `{"ok": true, "issued": [{"time": "2026-11-22T10:41:02", "id": "…", "service": "…", "key": "…"}]}`
У ушедшего `close` проекта список пустой. Для вложений добавлено поле `attachment`.

### `close` — закрыть доступ проекту

Запрос: `{"op": "close"}`
Ответ: `{"ok": true, "closed": true}`

Снимает одобрение со всех сессий проекта и отменяет его ожидающие запросы. Если хранилище больше никому не
нужно, посредник выгружает его из памяти.

### `shutdown` — только тестовый профиль

`{"op": "shutdown"}` → `{"ok": true}`. В профиле `main` команда недоступна: посредник останавливают
закрытием окна или меню владельца.

## Журнал

`logs/access.log` — строки с временем и событием: `access_requested`, `access_granted`, `access_denied`,
`access_expired`, `access_closed`, `value_issued`, `value_refused`, `attachment_issued`,
`attachment_refused`, `token_saved`, `token_save_refused`, `catalog_viewed`, `catalog_rebuilt`,
`password_failed`, `code_failed`, `admin_opened`, `record_changed`, `record_trashed`, `tags_changed`,
`cleanup_applied`, `trash_emptied`, `export_written`, `media_trusted`, `project_connected`,
`list_extended`, `queue_failed`.

В журнале бывают проект, сессия, pid, путь скрипта, сервис, имя ключа, номер строки и причина отказа.
Значений секретов и паролей там нет ни при каких обстоятельствах — это отдельное свойство, за ним следят
тесты.

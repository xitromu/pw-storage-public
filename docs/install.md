# Установка

Только Windows: нужны TPM 2.0 (поставщик «Microsoft Platform Crypto Provider»), Python 3.11+ с Tk
и приложение-аутентификатор TOTP. Telegram и KeePassXC для первого демо не нужны.
Команды ниже — для Windows Command Prompt (`cmd.exe`). Выбери новую папку: не устанавливай поверх
существующего хранилища. Если Git не установлен, скачай Code → Download ZIP со страницы репозитория.

## Требования и зависимости

| Компонент | Версия | Где используется |
|---|---|---|
| Windows | 10/11 x64 | TPM, именованные каналы, службы |
| Python | 3.11+ с Tk | всё приложение, `.venv`; базовый прогон проверялся на 3.11.9 |
| pykeepass | 4.2.0 | KDBX 4.0, Argon2id (1 GiB, 4 итерации, 4 потока) |
| pycryptodomex | 3.24.2 | шифрование внутри pykeepass |
| argon2-cffi | 25.1.0 | KDF хранилища и файла восстановления |
| pyotp | 2.9.0 | резервный второй фактор (TOTP) |
| pyzipper | 0.4.0 | архив выгрузки, AES-256 |
| lxml | 6.1.3 | зависит от pykeepass |
| sv-ttk | 2.6.1 | тёмная тема окон Tk |
| KeePassXC (GUI и CLI) | 2.8.0 | необязательный редактор; нужен для соответствующего теста совместимости |
| KeePass2 CLI | не используем | формат читает, теги проектов не сохраняет |

Проверить TPM: `tpm.msc` → «Безопасность устройства: TPM доступен для использования». Администратор не нужен —
ключи создаются от твоей учётной записи; для служб (шаг 5) нужен администратор.

## Шаг 1. Код и окружение

```bat
git clone https://github.com/xitromu/pw-storage-public.git C:\projects\pw-storage-public
cd /d C:\projects\pw-storage-public
install.bat
```

`install.bat` проверяет версию Python, создаёт `.venv` и ставит пакеты из `requirements.txt` с проверкой хешей.
Вручную то же самое:

```bat
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install --require-hashes -r requirements.txt
```

`requirements.txt` зафиксирован `uv pip compile --generate-hashes --only-binary :all:`. Неизвестный хеш или
другая сборка — установка прерывается, это ожидаемое поведение.

## Шаг 2. Проверка

```bat
set PW_STORAGE_REAL_TPM=0
set PYTHONUTF8=1
.venv\Scripts\python.exe -m unittest discover -s tests -t .
```

Базовый снапшот проверен полным прогоном: 793 теста, 3 пропуска. На твоей машине результат может отличаться.
Прогон занимает несколько минут, использует временные папки и фейковый TPM и необязателен для первого демо.
Аппаратная часть пройдёт отдельно, если установлены KeePassXC 2.8.0 (`C:\Program Files\KeePassXC\keepassxc-cli.exe`)
и включён `set PW_STORAGE_REAL_TPM=1`: такие тесты создают и удаляют только ключи `PW_STORAGE_TEST_*`.

## Шаг 3. Демо-хранилище

Профиль `test` живёт в `test_data` и наполняется случайными значениями вида `TEST-...` — его не жалко и
страшно не будет.

```bat
pw_menu.bat --profile test
```

Окно попросит пароль от 12 знаков, контрольный вопрос и ответ от 20 знаков.
Добавь показанный ключ в приложение-аутентификатор и введи его текущий шестизначный код.
После «Создать»:

- появится `test_data/vault.kdbx`, `test_data/recovery.json`, `test_data/catalog.bin`;
- на экране один раз покажут часть ключа восстановления — запиши её туда, где найдёшь без этого ПК;
- в `test_data/projects/DEMO_A` и `DEMO_B` лягут два демо-скрипта.

Закрой окно создания, нажми Enter для возврата в меню, затем `0` для выхода.
В той же командной строке запусти:

```bat
.venv\Scripts\python.exe -X utf8 test_data\projects\DEMO_A\demo.py
```

Демо запускает посредника автоматически. Выбери записи, введи тестовый пароль и подтверди TOTP.
Ожидаемый результат: успешные чтения одобренных записей и отказ для чужой, без печати значений.
Telegram в тестовом профиле выключен по умолчанию. Для ручного запуска тестового посредника есть `pw_console.bat`.
Закрытие окна посредника запрещает новые чтения; уже полученные значения остаются у процессов-получателей.

## Шаг 4. Боевое хранилище

```bat
pw_menu.bat
```

Порядок, который обычно удобен: создать хранилище → завести записи (пункт 2 или окно управления) →
подключить первый проект (окно «Проекты», [integrating-a-project.md](integrating-a-project.md)) →
поставить срок доступа по умолчанию.

Если на том же ПК уже есть KeePass-файл, переносить записи можно из KeePassXC: PW_STORAGE трогает только свои
свойства записей, но копию файла перед первым открытием сделай.

## Шаг 5. Службы без тебя (необязательно)

Служба Windows не может спросить пароль, поэтому ей выдаётся отдельный пакет секретов:

1. `deploy/services/<имя>.example.json` → копия без `example` и со своими строками (номера строк видно в окне управления);
2. `deploy/services/<имя>.launch.example.json` → как запускать процесс;
3. от администратора: `python -m pw_storage.service_host install --name PW_MYBOT --config deploy\services\mybot.launch.json --apply`;
4. `grant_service_read.bat PW_MYBOT C:\projects\MYBOT\.venv` — открыть учётной записи службы пакеты Python;
5. `provision_services.bat deploy\services\mybot.json` — выдать пакет из хранилища и перезапустить службу.

Подробности, каталоги и что делать при отказе — [operations.md](operations.md#службы-без-человека).

## Настройки профиля

`data/settings.json` создаётся сам при переключении Telegram; ключи необязательные, отсутствие файла — это значения по умолчанию.
Образец — `settings.example.json` (положи рядом со своим `data/settings.json`).

| Ключ | Значение по умолчанию | Смысл |
|---|---|---|
| `projects_root` | `C:\projects` | корень папок-проектов; проект = первая папка внутри него |
| `grant_hours` | `12` | срок доступа по умолчанию, от 1 до 8760 часов; в окне его можно поменять для конкретного запроса |
| `telegram` | `true` для `main`, `false` для `test` | просить ли подтверждение в Telegram; выключено — только окно и TOTP |
| `telegram_queue_lock` | нет | путь к файлу-запрету: нужен, если того же бота опрашивает ещё кто-то |
| `recovery_mail` | нет | подсказка в окнах, где лежит часть ключа восстановления; программа никуда ничего не отправляет |
| `trusted_media` | `[]` | серийные номера томов, которым разрешена выгрузка (заполняет окно выгрузки) |

Каталоги профиля (`data`, `logs`) вывести за пределы репозитория можно только правкой `PROFILES` в
`pw_storage/config.py` — файлы `data/*`, `logs/*`, `settings.json` и `test_data/` в `.gitignore`, так что
обычное случайное добавление исключено. Принудительное добавление и уже отслеживаемые файлы
`.gitignore` не защищает.

## Обновление

```bat
git pull
install.bat
```

Схема хранилища — обычный KDBX: после обновления файл по-прежнему открывается в KeePassXC. Изменения,
которые могут тебя коснуться, перечислены в релизах; миграций «на лету» программа не делает и не обещает.

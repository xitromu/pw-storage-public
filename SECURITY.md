# Безопасность

## Как сообщить о проблеме

Не публикуй работающий обход или секреты в открытом Issue.
Если доступна кнопка **GitHub → Security → Report a vulnerability**, используй её для приватного отчёта.
Пока приватный приём GitHub не включён, создай Issue **«Запрос приватного контакта по безопасности»**
без деталей уязвимости, кода обхода и данных; дождись согласования приватного канала с владельцем.
Обычные ошибки установки и документации можно сообщать через Issues на синтетических данных.

Укажи коммит (`git rev-parse --short HEAD`), Windows/Python, профиль (`main` или `test`), шаги воспроизведения
и ожидаемое поведение. Не прикладывай реальное хранилище, recovery-файл, TPM-пакет, ключи или необезличенный
журнал. Даже комментарии записей и причины запросов могут раскрывать личные сведения.

Фиксированного срока ответа и SLA нет. Если действующий секрет уже раскрыт, сначала отзови его у провайдера,
не дожидаясь ответа на отчёт.

## Если секрет раскрылся

1. **Отзови или замени секрет у провайдера.** Только внешний сервис может сделать старый токен недействительным.
2. **Прекрати новые чтения:** запусти `pw.py close` из папки нужного проекта или останови посредника,
   чтобы прекратить доступ всех проектов. Отдельно останови службы, которые уже получили значение.
3. **Замени запись в хранилище** и перевыпусти нужные пакеты служб. Старое значение может оставаться в
   прежних KDBX-копиях, истории записей, резервных архивах и памяти получателей.
4. **Смени пароль KDBX**, если он мог раскрыться, и перевыпусти данные восстановления при необходимости.
   Это защищает текущий файл, но не меняет пароль уже украденной копии.
5. Проверь метаданные журнала: какие проекты получали запись, когда и через какие процессы.

Утечка KDBX позволяет офлайн-подбор пароля. Если пароль известен злоумышленнику или может быть подобран,
ротируй секреты внутри утёкшей базы у их провайдеров. Смена пароля текущего KDBX не отзывает утёкшие токены
и не делает старый снимок нечитаемым.

## Что действительно даёт приложение

- Хранение значений в KDBX 4 с Argon2id вместо необходимости копировать их в файлы каждого проекта.
- Одобрение конкретных записей на срок; `ALL` разрешает запрос, а не автоматическую выдачу.
- Python API без команды, печатающей значение; штатный журнал содержит метаданные, не поле значения записи.
- Отдельные TPM-защищённые каталог, удалённый код и пакеты Windows-служб.
- Процедуры восстановления пароля, выгрузки и обслуживания.

Это не сертификация и не утверждение, что все пути утечки исключены.
[Полная модель угроз](docs/security-model.md) описывает границы и параметры.

## Что приложение не гарантирует

- Изоляцию вредоносного кода твоей учётной записи, администратора, клавиатурного шпиона или читателя памяти.
- Соблюдение правил AI-ассистентом: `AGENTS.md` — инструкция, не принудительный контроль.
- Безопасность значения после передачи скрипту: скрипт может его вывести, записать или отправить.
- Удаление прежних утечек из git, копий диска, архивов или внешних систем.
- Немедленный отзыв прав, изменённых другим окном или внешним редактором, в уже работающем посреднике.
  Для немедленного прекращения новых чтений используй `close` или остановку посредника.
- Исчезновение уже полученных значений после `close`, окончания срока или `revoke` пакета службы.

## Пароли, восстановление и метаданные

- Пароль хранилища вводится в скрытое локальное поле. KDBX хранит секреты зашифрованными;
  удалённый режим дополнительно хранит TPM-запечатанный пароль в `remote.bin`.
- Часть ключа восстановления показывается при создании/перевыпуске; её нужно хранить отдельно.
  Копия также находится **внутри зашифрованного KDBX** и включается в зашифрованную выгрузку.
- Для восстановления нужны `recovery.json`, ответ и часть ключа. Копия KDBX без известного пароля
  или подходящих данных восстановления не возвращает доступ.
- Комментарии каталога доступны до ввода пароля процессам в корне проектов. Журнал включает проекты,
  пути, имена ключей и введённые причины запросов. В эти поля нельзя вставлять секреты;
  перед пересылкой журналов нужна проверка и обезличивание.
- `.gitignore` предотвращает обычное случайное добавление, но не принудительное и не утечку уже отслеживаемых файлов.

## Telegram и работа без сети

Основной путь **пароль + локальный TOTP** работает без Telegram. В тестовом профиле Telegram выключен
по умолчанию; для основного его можно выключить настройкой `"telegram": false`.

При включении Telegram метаданные запроса — проект, комментарии записей, причина и срок — отправляются
в Telegram Bot API. Пароль KDBX для обычного подтверждения кнопкой не отправляется в чат.
Отдельный режим удалённого входа передаёт через чат **код доступа**, который раскрывает TPM-запечатанный
пароль на этом ПК. Это дополнительная граница доверия; не включай режим без понимания риска.

Бот пытается удалить сообщение с кодом, но удаление и исчезновение всех копий не гарантируются.
Неверные удалённые коды ограничиваются приложением: после трёх ошибок посредник прекращает удалённые
попытки в текущем запуске; у TPM есть свои механизмы ограничения подбора.

Телеметрии и облачной синхронизации приложение не реализует. Установка пакетов обращается к источникам
Python-зависимостей. Сетевые действия собственного скрипта-получателя не контролируются PW_STORAGE.

## Зависимости и проверки

`requirements.txt` фиксирует версии и хеши; `install.bat` использует `--require-hashes`.
Это проверка соответствия пакета выбранной сборке, **не доказательство отсутствия уязвимостей в зависимости**.
Обновления зависимостей требуют осознанного пересмотра и тестирования.

Тесты работают с синтетическими данными; аппаратные сценарии включаются отдельно.
Количество прошедших тестов не заменяет независимый аудит и оценку риска для твоего окружения.

## Security reports (English)

Use **GitHub → Security → Report a vulnerability** if private reporting is available. It is currently
not enabled: otherwise open an Issue requesting a private security contact, without vulnerability details,
exploit code or data, and agree on a private channel with the maintainer before sending a report.
Include the commit, OS/Python, profile and reproduction steps using synthetic data. Never attach real vaults,
recovery files, service packages or unredacted logs. There is no guaranteed response time; revoke exposed
credentials at their provider immediately. This project is not a sandbox, and tests are not an independent audit.
